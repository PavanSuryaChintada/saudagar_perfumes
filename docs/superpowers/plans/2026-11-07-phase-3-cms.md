# Phase 3 — CMS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every word, image, video, link and section a visitor sees comes from the database and is editable in the admin, with the current design unchanged.

**Architecture:** Five kinds of content.
- **Page sections:** `pages` + `website_sections` (`section_type` text, `config` jsonb).
- **Site-wide blocks:** `site_blocks` keyed singletons such as theme, brand, header, mega nav, footer and preloader.
- **Lists:** announcements, stories, reels, testimonials, FAQs, stockists.

One schema language describes every editable thing, and one `SchemaForm` renders the admin form for any of them. One registry maps each `section_type` to its component and its schema.

`site_bootstrap()` returns the blocks and live announcements in one round trip. Brand colours become Tailwind tokens backed by CSS variables, which the Theme block sets at runtime.

**Tech Stack:** Supabase Postgres, React 19, TanStack Query, @dnd-kit, TipTap, Tailwind 3 (CSS-variable colours), Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-07-saudagar-store-design.md` §11 (plus §17 SEO defaults).

## Global Constraints
- **No visitor-facing copy in component code.**
  - A component renders `config` (section) or `useBlock(key)` (site-wide).
  - Missing config renders nothing for that piece. It never renders invented text.
- **Defaults live in the seed:**
  - `0010_seed_cms.sql`, generated from `supabase/seed/cms.json`.
  - It carries today's content, so the site looks identical after the switch.
- **Saving:**
  - Changes are live on save.
  - Clearing a field removes it from the page.
- **Theme colours:**
  - Exactly 5 hardcoded brand colours become tokens:
    - `#C4823F` → `tk-accent`
    - `#ECC86A` → `tk-accent-night`
    - `#D4AF37` → `tk-gold`
    - `#111111` → `tk-ink`
    - `#0B0A0D` → `tk-night`
  - Neutral greys stay as they are.
- **Pages:** `home` and `story` can't be deleted. A new page is served at `/pages/:slug`.
- **Rich text** is sanitised on render with `sanitizeHtml`.
- **No browser dialogs.** Admin lists can be reordered by drag and keyboard.
- **Commits:** no Claude co-author trailer.

## Review Focus
1. A section whose config is missing a field (or has an empty list) renders without crashing and shows nothing invented. *(Task 4 registry test renders every type with `{}`.)*
2. A hidden section, or an unpublished page, never shows to visitors, but the admin preview link still works for admins. *(Task 1 SQL test.)*
3. An announcement outside its start/end window (IST) doesn't show. *(Task 1 SQL test.)*
4. Deleting `home` or `story` is refused with a readable message. *(Task 1 SQL test.)*
5. Internal links (collection, category, note, product, page) resolve to the right path, and external links open safely. *(Task 2 `resolveLink` test.)*

### Task 1: CMS schema and RPCs
**Files:** `supabase/migrations/0009_cms.sql`, `supabase/tests/0009_cms.test.sql`

**Produces:**
- **Tables:**
  - `pages(slug, title, layout 'sections'|'rich_text', body, seo_title, seo_description, og_image, is_published, is_system)`
  - `website_sections(page_id, section_type, position, is_visible, config)`
  - `site_blocks(key pk, value jsonb)`
  - `announcements(text, link, is_active, starts_at, ends_at, position)`
  - `stories`
  - `reels` + `reel_products`
  - `testimonials`
  - `faqs`
  - `stockists`
- **RPCs:**
  - `site_bootstrap()` returns `{settings, blocks, announcements}`
  - `page_content(p_slug)`
  - `duplicate_section(p_id)`
  - `reorder_rows` gains the CMS tables
- **RLS:** public reads published/visible/active rows; admins read and write everything.

Steps: SQL tests (Review Focus 2–4 plus RLS) → FAIL → migration → PASS → commit.

### Task 2: CMS core library (pure, tested)
**Files:** `src/cms/types.ts`, `src/cms/links.ts`, `src/cms/sources.ts`, `src/cms/schema.ts`, plus tests

**Produces:**
- **Types:** `FieldDef` is one of:
  - text, textarea, richtext, number, boolean, select, color, media (image/video)
  - link, product_source, list (with `fields` and `itemLabel`), group
  - Any field can carry `showIf`.
- **Functions:**
  - `resolveLink(link) → {href, external}`
  - `sourceToSearchPayload(source) → search_products payload`
  - `setAtPath`, `getAtPath`
  - `visibleFields(fields, value)`, which applies `showIf`
  - `emptyValueFor(field)`

**E2E tests:**
- The admin edits a home section heading → the home page shows it.
- The admin hides a section → it disappears.
- The admin adds an announcement → the bar shows it.
- The admin creates a rich-text page → `/pages/<slug>` renders it.
